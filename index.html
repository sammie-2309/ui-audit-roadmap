01
Week 1 · Days 1, 2 & 3
UI Audit & Discovery
Audit
Goals
  • Develop a complete cross-platform picture of the current product desktop, tablet, and mobile
  • Surface all major inconsistencies in layout, spacing, typography, colour, and components
  • Identify key usability and accessibility gaps against WCAG 2.1 AA
  • Align on a high-level visual direction for the system going forward
Deliverables
Audit Report
  • Annotated UI audit across all breakpoints with documented issues
  • Issue log organised by element and component, covering layout, spacing, typography, and colour with an inventory of existing styles
  • Visual direction moodboard and design language brief (2–3 directions)
Expected Outcomes
  • Shared understanding of the current state and its most painful failure points
  • Stakeholder consensus on visual direction and design system tone
  • A clear list of elements and components to build in Week 2, informed by the audit findings
Check-ins
Day 1 Kick-off & access handover via Figma
Day 2 Audit preview shared in Figma (async comments)
Day 3 Audit readout & direction sign-off via Figma
02
Week 2 · Days 4, 5 & 6
Design System Foundations
Build
Goals
  • Establish a token-first design architecture primitives mapped to semantic aliases
  • Define foundational tokens: colour, typography, spacing, radius, and elevation motion and interaction patterns to follow once foundations are settled
  • Build the most-used components as reusable, well-documented Figma variants
  • Lay the structural foundation for future team adoption and product expansion
Deliverables
Token Library + Core Components
  • Token file colour primitives, semantic aliases, spacing scale, radius, elevation
  • Typography system type roles, font pairing, size scale, line height, weight
  • Figma component library: Button, Input, Select, Checkbox, Radio, Modal, Card, Badge, Table row, Navigation bar, Form layout
  • Light mode by default, dark mode available as an optional add-on
  • Naming conventions doc and brief contributor guide
Expected Outcomes
  • A shared source of truth for design decisions no more ad hoc colour or spacing choices
  • Components that are production-ready, variant-rich, and documented for developer handoff
  • A scalable architecture that grows as the product does no throw-away work
  • Team confidence that the system reflects the agreed visual direction from Week 1
Check-ins
Day 4 Token review & component scope alignment via Figma
Day 5 Component WIP review (async Figma comments)
Day 6 Library hand-off via Figma
03
Week 3 · Days 7, 8 & 9
Feature Redesign Example
Demonstrate
Goals
  • Select one representative, self-contained feature agreed with the client at kick-off or during Week 1
  • Redesign it end-to-end using only system-defined tokens and library components
  • Show how the design system elevates the feature: improved hierarchy, clarity, and visual quality
  • Produce a handoff-ready file that the dev team can immediately act on
Deliverables
Redesigned Feature + Handoff
  • Desktop + mobile redesign of the chosen feature core happy path only
  • Side-by-side before/after comparison shared in Figma
  • Annotated design spec (spacing, tokens, component states)
  • Interaction notes for key UI moments (focus states, empty states, loading)
  • Annotated Figma file shared for stakeholder review via async comments
Expected Outcomes
  • Tangible, real-world proof that the design system improves the product
  • A referenceable template for how the team should approach future feature work
  • Developer-ready specs that accelerate implementation without additional design effort
  • A clear path for the client to keep building on the system after the engagement
  • Before/after comparison of UI inconsistencies to show measurable progress
Check-ins
Day 7 Feature scope confirmation & design kick-off via Figma
Day 8 Design WIP review (async Figma comments)
Day 9 Final Figma file delivery & engagement close
Scope Principles
  • Scoped to the core design layer only Figma files, token definitions, and design specs
  • Engineering implementation, Storybook setup, and product rollout are not included this engagement is design-only
  • The Week 3 feature redesign covers the primary user flow only
  • Edge cases, error states beyond the component library, and admin variants are deferred to a follow-on engagement
What We Need From You
  • Access to the current product staging login or existing Figma files
  • Any existing brand guidelines or Figma files
  • One key stakeholder point of contact for async review
  • Week 3 feature decision ideally confirmed at kick-off, or no later than the end of Week 1
  • A shared Figma workspace from Day 1
Collaboration Model
  • Part-time engagement 3 days per week, ideally Monday, Wednesday, and Friday
  • Exact days agreed at kick-off to suit your team's schedule
  • Off-days are built in for async review without calendar pressure
  • Each phase ends with a Figma file delivery and sign-off before the next phase begins
  • Decisions made at each phase gate are locked to protect timeline and quality
After the Engagement
  • Production-ready Figma component library with documented variants
  • A full token architecture file ready for developer handoff
  • A real feature redesign demonstrating the system in action
  • All assets designed to be extended by your in-house team or via a follow-on retainer
  • Not locked to any proprietary toolchain
